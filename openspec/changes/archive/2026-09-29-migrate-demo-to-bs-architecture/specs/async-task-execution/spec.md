# Spec Delta

## Purpose

定义长耗时任务的行为：用户提交后立即得到任务标识，页面可查看分步进度；任务执行期间系统保持可响应；任务结果或失败原因都必须显式返回。

## ADDED Requirements

### Requirement: 异步提交

长耗时操作（网格离散、配准、质量评估等）必须（MUST）以异步任务方式执行：提交后立即返回任务标识，执行期间系统必须保持可响应。

#### Scenario: 提交立即返回

- **WHEN** 用户提交网格离散任务
- **THEN** 立即得到任务标识，页面可继续操作

#### Scenario: 执行期间保持响应

- **GIVEN** 一个长任务正在执行
- **WHEN** 用户查询任务进度或浏览其他页面
- **THEN** 请求正常响应，不因任务执行而阻塞

### Requirement: 并发与排队

系统必须（MUST）支持在配置的并发容量内并行执行任务；超出容量的任务必须保持排队状态，直至有执行容量。

#### Scenario: 容量内并行

- **WHEN** 同时提交的任务数不超过并发容量
- **THEN** 多个任务可并行推进

#### Scenario: 超容量排队

- **WHEN** 提交的任务数超过并发容量
- **THEN** 多余任务显示为排队中，并在容量释放后开始执行

### Requirement: 分步进度

任务必须（MUST）按原演示的阶段语义上报进度（如质量评估的"第 N/4 步"）；前端必须可查看各阶段进度。

#### Scenario: 查看阶段进度

- **WHEN** 用户查看执行中的质量评估任务
- **THEN** 可看到当前阶段与已完成阶段

#### Scenario: 完成状态

- **WHEN** 任务完成
- **THEN** 状态更新为成功，并指向产出的产物

### Requirement: 失败显式

任务失败时系统必须（MUST）返回并展示失败原因（不得静默失败或用默认值掩盖）；失败的任务不得产生可被误用的产物。

#### Scenario: 参数非法

- **GIVEN** 用户提交了非法的任务参数
- **WHEN** 任务执行失败
- **THEN** 状态为失败并展示具体原因，会话清单不新增误导性产物

#### Scenario: 执行异常

- **WHEN** 任务执行过程中出现异常
- **THEN** 页面展示失败原因，且任务不产生成功状态

### Requirement: 中断与重启

服务重启导致运行中任务中断时，系统必须（MUST）将相关任务显式标记为失败或中断并给出原因，不得停留在"执行中"或误报成功。

#### Scenario: 重启后标记中断

- **GIVEN** 有任务正在执行
- **WHEN** 服务重启
- **THEN** 该任务显示为中断或失败，并说明原因
