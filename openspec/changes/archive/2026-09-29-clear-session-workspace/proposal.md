# Proposal

## Why

当前浏览器会话的 `data/sessions/<session_id>/` 会持续保留上传文件、任务中间文件、预览和产物，用户没有清理入口；长期使用会占用磁盘，且无法在不更换浏览器的情况下快速重置工作区。删除大目录可能阻塞 Web API，因此需要由独立进程执行，并通过 SSE 向页面反馈进度和结果。

## What Changes

- 在左侧导航栏最底部新增“清空会话文件”按钮，仅作用于当前浏览器会话，不提供服务器文件系统交互。
- 点击后先二次确认，再通过 `POST /api/session/clear` 建立 `text/event-stream` 流；事件至少包含 `started`、`success`、`error`。
- 后端在确认不存在排队/运行任务和未完成上传后，使用独立 `spawn` 子进程删除当前 `data/sessions/<session_id>/` 目录，避免目录删除阻塞事件循环。
- 删除成功后前端提示“删除成功”，刷新会话快照；旧会话目录不存在时，沿用现有中间件在下一次请求建立新会话。
- 删除失败、请求冲突或网络异常必须显式提示；清空过程中按钮进入加载/禁用状态，禁止重复提交。
- 现有任务提交、上传和任务进度轮询保持不变；仅本功能新增 SSE 传输方式。

**BREAKING**: 清空操作会删除当前会话目录中的全部数据和文件，且不可恢复；不会删除其他会话目录。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `session-workspace`: 增加当前会话目录的显式清空能力，要求隔离删除、独立进程执行、活跃操作保护、SSE 结果反馈以及失败时不误报成功。
- `web-demo-shell`: 增加左侧导航底部清空入口、确认与执行状态、成功弹窗和失败反馈，并保持不暴露服务器路径或打开文件夹操作。

## Impact

- 后端：新增会话清空 API/SSE 流与 `spawn` 子进程清理逻辑，涉及会话 API、应用状态装配和会话存储边界；不新增第三方依赖。
- 前端：修改应用外壳导航布局，新增清空 API/SSE 解析逻辑，并在成功后刷新 Pinia workspace 快照。
- 测试：需要覆盖子进程删除成功/失败、路径越界拒绝、活跃任务/上传冲突、SSE 事件顺序及前端事件解析。
- 运维与数据：删除是破坏性操作；无法从应用内恢复已删除目录。多 Web 实例共享同一数据根目录仍不在本次支持范围内。

## Assumptions

- “清空对应 session 的文件目录”按删除整个 `data/sessions/<session_id>/` 处理，而不是只清空 `artifacts/`、`uploads/`、`previews/` 或 `work/` 中的部分内容。
- 当前会话存在 `queued`/`running` 任务或状态为 `uploading`/`completing` 的上传时，清空请求返回冲突，不强制删除，避免破坏正在执行的工作。
- 本功能不引入可恢复的回收站；删除成功后由现有会话中间件创建新的空会话。

## Rollback

- 代码回滚：移除前端入口并取消 `POST /api/session/clear` 路由注册；恢复 `App.vue`、会话 API 和新增清理模块的改动即可回到原有行为。
- 数据回滚：已删除的会话目录无法由应用恢复，必须在发布前备份 `data/sessions/` 或仅在明确接受破坏性操作的环境中启用。
- 若 SSE 实现导致生产兼容问题，可先隐藏按钮并保留服务端路由，待修复后再恢复入口；不得用轮询伪装成功结果。

## Coordination

- 前后端接口必须在同一变更内合并，确保 `text/event-stream` 事件名、错误载荷和冲突状态码一致。
- 发布负责人需确认部署环境的会话目录不会被外部系统当作持久化数据源；本仓库当前只有前端、后端和测试维护者，无外部团队依赖。
