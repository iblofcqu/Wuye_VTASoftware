# Spec Delta

## Purpose

定义大文件上传与断点续传行为：上传在网络中断、页面刷新或服务重启后必须能够从已完成的进度继续，并且只有在完整性校验通过后才登记为可用产物。

## ADDED Requirements

### Requirement: 分片上传与断点续传

系统必须（MUST）支持将大文件拆分为多个部分上传，并允许在中断后仅补传缺失部分；重复提交同一部分不得产生重复数据或错误。

#### Scenario: 中断后续传

- **GIVEN** 一个文件的上传在中途因网络中断而停止
- **WHEN** 客户端恢复网络并继续上传该文件
- **THEN** 系统从已接收的进度继续，不要求重新上传已完成的部分

#### Scenario: 分片重复提交

- **WHEN** 客户端重复提交同一个已接收的分片
- **THEN** 系统保持幂等，最终文件内容不变

#### Scenario: 上传进度可见

- **GIVEN** 一个文件正在上传
- **WHEN** 用户查看上传列表
- **THEN** 显示每个文件的上传进度与状态（上传中、失败、已完成）

### Requirement: 上传状态持久与恢复

上传进度必须（MUST）持久化，页面刷新或服务重启后必须能够查询已接收部分并继续上传。

#### Scenario: 刷新页面后继续

- **GIVEN** 一个未完成的上传
- **WHEN** 用户刷新页面后重新选择同一文件并选择继续
- **THEN** 系统返回已接收的部分，客户端从缺失部分继续上传

#### Scenario: 服务重启后继续

- **GIVEN** 一个未完成的上传
- **WHEN** 服务重启
- **THEN** 上传记录与已接收分片仍然有效，可继续完成上传

### Requirement: 完整性校验

上传必须（MUST）经过完整性校验：分片校验失败或最终文件与声明不一致时，上传必须失败并显式提示，且不得登记为可用产物。

#### Scenario: 分片校验失败

- **WHEN** 服务端检测到某个分片校验不通过
- **THEN** 该分片被视为未完成，提示失败原因并允许重新上传

#### Scenario: 完成后整体校验

- **WHEN** 所有分片上传完毕并请求完成上传
- **THEN** 系统校验整体文件，通过后才登记为会话产物

### Requirement: 上传清理与边界

未完成的上传必须（MUST）可被取消，并在超过保留期限后自动清理；超出大小上限的文件必须被显式拒绝。

#### Scenario: 取消上传

- **WHEN** 用户取消一个未完成的上传
- **THEN** 服务端删除其已接收的分片，不再占用空间，且不登记产物

#### Scenario: 过期清理

- **WHEN** 一个上传超过配置的保留期限仍未完成
- **THEN** 系统自动清理该上传的临时数据

#### Scenario: 超出大小上限

- **WHEN** 文件大小超过配置的上限
- **THEN** 上传被拒绝并显示明确原因
