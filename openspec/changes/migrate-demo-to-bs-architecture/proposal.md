# Proposal

## Why

`base_software` 是基于 Streamlit 的演示程序：界面虽然通过浏览器访问，但文件选择依赖服务器端 tkinter 对话框，输出交付依赖 `os.startfile` 打开服务器文件夹。部署到服务器后，局域网用户看不到、也无法选择自己电脑上的文件（五冶反馈的两个使用问题即由此而来）。五冶既有系统希望以一个按钮跳转到该软件的 Web 页面，因此需要把演示重构为前后端分离的 B/S 应用：浏览器负责文件交换与交互展示，后端负责计算与产物管理。

## What Changes

- 新增 `frontend/`：Vue 3 + TypeScript（Vite + Element Plus），复刻原 demo 的界面结构（首页、侧边栏导航、说明书、分步表单）；3D 预览用 vtk.js，直方图用 Plotly.js。
- 新增 `backend/`：FastAPI 服务（uv 管理依赖），提供上传/下载、会话工作区、异步任务与产物接口；算法模块从 `base_software/functions` 原样搬迁，不做任何行为修改。
- 文件交互全部改为浏览器方式：上传输入文件、下载结果与报告；移除 tkinter 对话框、`os.startfile` 与 `cache/*.txt` 路径协议。
- 大文件上传支持断点续传：上传按分片进行、可重试、可续传（页面刷新或服务重启后仍可继续），完成后通过完整性校验才登记为产物；未完成上传可取消并自动过期清理。
- 新增会话工作区：每个浏览器会话独立目录 + `session.json` 清单；中间产物登记后可在后续步骤直接选择，不需要重复上传，任一步仍可上传新文件。
- 长耗时操作（网格离散、配准、质量评估等）改为异步任务：Web 进程提交到计算进程池后立即返回任务号，前端可见分步进度与失败原因；进程池容量可配置。
- 3D 预览在服务端轻量化（默认 ≤100 万点，可配置）后以二进制传给浏览器渲染；全量点云只参与计算。
- 交付形态：Linux 裸机 + uv 启动脚本 + 依赖安装清单（TeX Live/ctex、Chromium、离屏渲染依赖、中文字体）；FastAPI Web 进程同时提供 API 与前端静态资源，重计算全部交给独立进程池执行。Docker 镜像不在本变更范围，后续独立变更处理。
- `base_software/` 原样保留，仅作为行为基线与回归对比来源，不再演进。
- 明确不改变：各算法输入输出行为（含已知缺陷）、结果文件命名与格式、PDF 报告版式与内容、原有界面文案与操作流程。

## Capabilities

### New Capabilities

- `web-demo-shell`: 浏览器端页面框架（首页、导航、说明书、分步表单）与无登录的跨局域网访问；替代服务器端文件对话框与"打开输出文件夹"。
- `session-workspace`: 会话隔离目录与清单、产物登记、会话内选择复用与结果下载。
- `resumable-file-upload`: 大文件分片上传、断点续传与完整性校验，未完成上传的取消与过期清理。
- `async-task-execution`: 任务提交到独立计算进程池异步执行、Web 服务不被阻塞、分步进度上报、失败原因显式返回。
- `point-cloud-preprocessing`: 网格离散、尺寸缩放、下采样（体素/均匀）、配准（FPFH 粗配准 + ICP 精配准）行为与原 demo 严格一致，含输出命名与会话内交接。
- `dimension-quality-assessment`: 偏差计算（Point2Point/Point2Plane）、剔除比例统计、偏差直方图与统计指标、PDF 报告生成。
- `point-cloud-preview`: 轻量化 3D 预览的生成与浏览器交互（旋转/缩放、双点云配色、误差色带）。

### Modified Capabilities

无（`openspec/specs/` 当前为空，本变更全部为新增能力）。

## Impact

- 代码：新增 `frontend/`、`backend/`；`base_software/` 不做修改；根目录 README 与运行文档需同步更新。
- 运行环境：目标 Linux 服务器需要 uv、TeX Live（含 ctex 与中文字体）、Chromium（kaleido 导出图片）、离屏渲染支持（EGL/OSMesa 或 xvfb + mesa）；提供安装清单与启动脚本。
- 对现有功能的影响：`base_software` 演示可继续独立运行，行为不变；本变更完成后由新 Web 版本作为演示入口。
- 接口：新增内部 HTTP 接口（上传/下载、会话、任务、产物、预览）；不新增对外部系统的接口依赖。
- 数据：仅按会话在服务器磁盘保存上传文件与产物（含未完成上传的临时分片），无数据库；会话清单为 JSON，未完成上传按保留期限清理。
- 风险：Linux 离屏渲染与中文字体是部署阶段主要不确定性；算法搬迁的严格一致性依赖 golden 对比锁定；大文件上传带来磁盘占用，需要未完成上传的过期清理策略。

## Rollback Plan

- 本变更只新增 `frontend/`、`backend/` 与文档，`base_software/` 不动；回滚 = 停止新服务并删除新增目录与文档改动，即可恢复到变更前状态，无需数据迁移。
- 若仅部分模块迁移失败：按 capability 粒度回退对应前后端代码与任务清单，其余模块保持可用。
- 会话数据（`data/sessions/`）均为演示数据，可整体删除，不涉及持久业务数据。

## Coordination

- 五冶：确认按钮跳转的目标 URL、服务器网络与端口可达性、演示点云数据来源。
- 算法维护者：确认"行为严格不变"的验收方式（golden 对比样例与容差）。
- 部署负责人：确认 Linux 服务器可用性、依赖安装范围（TeX Live/Chromium/字体/离屏渲染）与 uv 启动方式。
