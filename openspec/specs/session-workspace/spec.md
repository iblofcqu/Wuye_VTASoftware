# session-workspace Specification

## Purpose

定义会话工作区的行为：每个浏览器会话拥有相互隔离的文件空间与产物清单，用户上传的输入与任务产物持续保留在会话内，可被后续步骤直接选用并通过浏览器下载。

## Requirements

### Requirement: 会话建立与隔离

系统必须（MUST）为每个浏览器会话建立独立的工作区；不同会话之间的上传文件与产物必须互不可见、互不覆盖。

#### Scenario: 首次访问建立会话

- **WHEN** 浏览器首次访问系统
- **THEN** 系统分配会话，并在后续请求中始终使用同一工作区

#### Scenario: 会话隔离

- **GIVEN** 两个浏览器会话同时使用系统
- **WHEN** 各自上传同名文件并运行任务
- **THEN** 两个会话的产物互不影响、互不可见

### Requirement: 文件上传

系统必须（MUST）允许用户从本机上传输入文件；可接受的文件范围必须与原演示的读取能力一致；只有完整上传并通过完整性校验的文件才登记为会话产物；上传失败、被取消或超限时，系统必须显式提示且不得产生任何产物登记。

#### Scenario: 成功上传

- **WHEN** 用户上传一个受支持格式的文件且上传完整、校验通过
- **THEN** 该文件进入当前会话并出现在可选产物列表中

#### Scenario: 多文件上传

- **WHEN** 用户一次选择多个文件上传
- **THEN** 每个文件独立登记、独立报错，任一文件失败不影响其他文件

#### Scenario: 上传失败

- **WHEN** 上传被中断、完整性校验失败或文件类型不受支持
- **THEN** 页面显示具体失败原因，且会话清单不新增条目

### Requirement: 产物登记

每次任务成功完成时，系统必须（MUST）将输出登记到当前会话的产物清单，记录显示名称、类型、来源任务、生成时间与大小。

#### Scenario: 登记产物

- **WHEN** 某个任务成功完成
- **THEN** 会话清单中出现该产物，且上述信息完整

#### Scenario: 列出产物

- **WHEN** 用户打开会话产物列表
- **THEN** 能看到当前会话的全部可用产物

### Requirement: 会话内复用

后续步骤必须（MUST）允许直接从当前会话清单选择已有产物作为输入，不需要重复上传；同时必须允许随时上传新文件。

#### Scenario: 复用产物

- **GIVEN** 会话中已有粗配准产物
- **WHEN** 用户进入精配准步骤
- **THEN** 可直接选择该产物作为移动点云输入

#### Scenario: 混合来源

- **WHEN** 用户在同一表单中需要两个输入
- **THEN** 可分别选择会话产物或上传新文件

### Requirement: 结果下载

会话中的点云产物与 PDF 报告必须（MUST）可通过浏览器下载，下载文件名必须与原演示的产物命名规则一致。

#### Scenario: 下载点云

- **WHEN** 用户对某个点云产物选择下载
- **THEN** 得到与原演示命名规则一致的文件

#### Scenario: 下载报告

- **WHEN** 用户下载 PDF 报告
- **THEN** 文件名符合"点云名 + 几何质量评估报告 + 日期"规则

### Requirement: 清单持久与恢复

会话清单必须（MUST）以文件形式持久化；服务重启后，已完成产物仍必须可被列出与下载。

#### Scenario: 重启后恢复

- **GIVEN** 会话中已有成功产物
- **WHEN** 服务重启且同一浏览器再次访问
- **THEN** 产物列表仍包含这些产物并可下载

### Requirement: 清空当前会话工作区

系统必须（MUST）允许用户清空当前浏览器会话的工作区。清空请求只能删除请求所绑定会话的会话目录及其全部内容，不得读取、修改或删除其他会话；清空完成后，下一次会话请求必须建立新的空工作区。

#### Scenario: 成功清空当前会话

- **GIVEN** 当前会话目录包含上传文件、任务工作目录、预览缓存或已登记产物，且同时存在另一个会话目录
- **WHEN** 用户在确认后发起清空并等待清空流程完成
- **THEN** 系统删除当前会话目录，不对另一个会话目录产生任何影响，并且后续会话请求返回空的产物、任务和上传列表

#### Scenario: 清空失败不误报成功

- **GIVEN** 独立删除进程因权限、文件占用或文件系统错误无法完成删除
- **WHEN** 清空流程结束
- **THEN** 系统必须显式报告失败原因且不得发送成功结果，页面不得提示删除成功

### Requirement: 清空过程使用 SSE 反馈

系统必须（MUST）通过 `text/event-stream` 流式反馈清空请求的执行状态；流必须至少区分开始、成功和失败三类结果，并在成功后结束。清空过程必须由独立进程执行，目录删除期间 Web API 必须保持可响应。

#### Scenario: 接收清空事件

- **GIVEN** 当前会话不存在排队/运行任务和未完成上传
- **WHEN** 客户端发起清空请求
- **THEN** 客户端先收到开始事件，随后收到成功事件或携带具体原因的失败事件，成功事件之后连接结束

#### Scenario: 删除期间 Web API 保持响应

- **GIVEN** 一个较大的会话目录正在由独立进程删除
- **WHEN** 客户端保持 SSE 连接并同时请求其他 API
- **THEN** 其他 API 不需要等待目录删除完成即可返回，且 SSE 连接仍能收到最终结果

### Requirement: 清空操作的冲突保护

系统必须（MUST）在删除前检查当前会话是否存在未完成工作；当存在 `queued`/`running` 任务、`uploading`/`completing` 上传或同一会话的另一清空操作时，系统必须拒绝新的清空请求并保持会话目录不变。

#### Scenario: 存在运行或排队任务

- **GIVEN** 当前会话存在状态为 `queued` 或 `running` 的任务
- **WHEN** 用户发起清空
- **THEN** 系统以显式冲突错误拒绝请求，当前会话目录和任务状态保持不变

#### Scenario: 存在未完成上传

- **GIVEN** 当前会话存在状态为 `uploading` 或 `completing` 的上传
- **WHEN** 用户发起清空
- **THEN** 系统以显式冲突错误拒绝请求，当前会话目录和上传状态保持不变

#### Scenario: 重复或并发清空

- **GIVEN** 当前会话已有一个清空操作正在进行
- **WHEN** 同一会话再次发起清空
- **THEN** 系统拒绝第二次请求，且不得启动第二个删除进程

### Requirement: 清空路径安全边界

系统必须（MUST）仅以当前请求的合法会话标识解析并校验会话目录；非法会话标识、解析到会话根目录之外的路径或目标不是独立会话目录时，系统必须拒绝删除。

#### Scenario: 拒绝越界目录

- **GIVEN** 请求携带非法会话标识或解析出的目标不属于会话根目录下的独立会话目录
- **WHEN** 系统处理清空请求
- **THEN** 系统拒绝删除并显式返回错误，且任何会话根目录之外的路径均不被删除
